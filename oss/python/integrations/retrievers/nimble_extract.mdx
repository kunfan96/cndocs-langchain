title: Nimble Extract
---

>[Nimble 的 Extract API](https://docs.nimbleway.com/nimble-sdk/extract-api) 通过使用无头浏览器浏览特定 URL 来提取渲染后的内容，而非依赖缓存或受 API 限制的数据。此检索器能够处理 JavaScript 渲染、动态内容和复杂的导航流程——使其适用于需要访问特定网页（包括分页、过滤器和客户端渲染背后的内容）的 RAG 应用程序。

我们可以将其用作[检索器](/oss/python/langchain/retrieval)。它将展示此集成特有的功能。了解之后，探索[相关的用例页面](/oss/python/langchain/rag)以学习如何将此检索器作为更大链的一部分使用可能会很有用。

### 安装

<CodeGroup>
```bash pip
pip install -U langchain-nimble
```
```bash uv
uv add langchain-nimble
```
</CodeGroup>

我们还需要设置 Nimble API 密钥。您可以通过在 [Nimble](https://www.nimbleway.com/) 注册来获取 API 密钥。

```python
import getpass
import os

if not os.environ.get("NIMBLE_API_KEY"):
    os.environ["NIMBLE_API_KEY"] = getpass.getpass("Nimble API key:\n")
```

## 用法

现在我们可以实例化我们的检索器：

```python
from langchain_nimble import NimbleExtractRetriever

# 基本检索器 - 需要要提取的 URL
retriever = NimbleExtractRetriever()
```

## 在链中使用

我们可以轻松地将此检索器组合到 RAG 链中，以提取和分析特定的网页内容：

```python
from langchain_core.output_parsers import StrOutputParser
from langchain_core.prompts import ChatPromptTemplate
from langchain_core.runnables import RunnablePassthrough
from langchain_openai import ChatOpenAI

# 创建一个 RAG 提示
prompt = ChatPromptTemplate.from_template(
    """分析从提供的 URL 中提取的内容。
仅根据提取的内容回答问题。
如果无法根据内容回答，请说明。

内容：{content}

问题：{question}

回答："""
)

llm = ChatOpenAI(model="gpt-4o-mini")

# 配置检索器以进行内容提取
retriever = NimbleExtractRetriever(
    parsing_type="markdown",
    wait=3000
)


def format_docs(docs):
    return "\n\n".join(doc.page_content for doc in docs)


# 示例：从 LangChain 文档中提取和分析内容
urls = [
    "https://python.langchain.com/docs/concepts/retrievers/",
    "https://python.langchain.com/docs/concepts/tools/",
    "https://python.langchain.com/docs/tutorials/agents/"
]

# 创建一个自定义的可运行对象，将 URL 传递给检索器
def get_docs(question):
    # 在真实场景中，URL 可能由之前的步骤决定
    return retriever.invoke(urls)


# 构建 RAG 链
chain = (
    {
        "content": lambda _: get_docs(_) | format_docs,
        "question": RunnablePassthrough()
    }
    | prompt
    | llm
    | StrOutputParser()
)
```

```python
# 对提取的内容提出一个问题
response = chain.invoke("LangChain 中检索器和工具之间的主要区别是什么？")
print(response)
```

```output
根据提取的 LangChain 文档，以下是主要区别：

**检索器：**
- 基于非结构化查询进行文档检索的接口
- 主要用例是 RAG（检索增强生成）
- 从向量存储等各种来源返回文档
- 专注于语义搜索和信息检索
- 问答系统的核心组件

**工具：**
- 代理与外部系统交互的接口
- 实现超出文本生成的操作（API 调用、计算、网络搜索）
- 由代理用于动态扩展功能
- 支持同步和异步执行
- 可以链接在一起以实现复杂的工作流

**代理：**
- 使用工具完成任务的高级编排器
- 决定使用哪些工具以及何时使用
- 可以组合多个工具来解决复杂问题
- 教程展示了如何构建具有工具集成的代理工作流

文档强调，检索器专门用于信息检索，而工具为代理提供了更广泛的操作能力。
```

## 高级配置

检索器支持用于 URL 提取的广泛配置：

| 参数 | 类型 | 默认值 | 描述 |
|-----------|------|---------|-------------|
| `parsing_type` | str | "plain_text" | 输出格式："plain_text"、"markdown" 或 "simplified_html" |
| `driver` | str | "vx6" | 浏览器驱动程序版本："vx6"（快速）、"vx8"（平衡）或 "vx10"（全面） |
| `wait` | int | None | 等待页面加载的毫秒数（0-60000） |
| `render` | bool | True | 启用 JavaScript 渲染 |
| `locale` | str | "en" | 页面区域设置偏好（例如 "en-US"） |
| `country` | str | "US" | 用于本地化内容的国家/地区代码（例如 "US"） |
| `api_key` | str | 环境变量 | Nimble API 密钥（默认为 NIMBLE_API_KEY 环境变量） |

**高级配置示例：**

```python
from langchain_nimble import NimbleExtractRetriever

# 针对 JavaScript 密集型文档站点优化的检索器
retriever = NimbleExtractRetriever(
    parsing_type="markdown",
    driver="vx10",  # 使用全面驱动程序处理复杂的 SPA
    wait=5000,  # 等待最多 5 秒以完成页面渲染
    render=True,  # 启用 JavaScript 渲染
    locale="en-US",
    country="US"
)

# 从特定的 LangChain 文档页面提取内容
docs = retriever.invoke([
    "https://python.langchain.com/docs/concepts/chat_models/",
    "https://python.langchain.com/docs/concepts/prompts/"
])
```

## 最佳实践

### 驱动程序选择

- **vx6**（默认）：适用于标准网站的快速提取
- **vx8**：适用于中等复杂网站的平衡性能
- **vx10**：适用于 JavaScript 密集型 SPA 和复杂动态内容的全面渲染

### 页面加载配置

- **无等待**（`wait=None`）：大多数现代网站的默认设置
- **短等待**（`wait=1000-2000`）：适用于具有延迟加载或延迟内容的页面
- **较长等待**（`wait=5000+`）：适用于加载缓慢的 SPA 或需要时间完全渲染的繁重 JavaScript

### 输出格式选择

- **纯文本**（默认）：快速提取原始文本内容
- **Markdown**：最适合 RAG - 保留标题、列表、代码块等结构
- **HTML**：当您需要保留详细的样式或结构信息时

### 性能优化

1. **调整等待时间**：仅在必要时使用——快速网站不需要等待时间
2. **批量处理相关 URL**：并行提取来自同一域的多个页面
3. **选择正确的格式**：RAG 使用 Markdown，更简单的处理使用 plain_text
4. **使用异步**：利用 `ainvoke()` 进行并发 URL 提取
5. **验证内容**：在处理之前检查页面是否成功加载
