>[Nimble 的搜索 API](https://docs.nimbleway.com/nimble-sdk/search-api) 通过使用无头浏览器浏览实时网络来提供实时网络搜索，而非查询预构建的索引。此检索器处理 JavaScript 渲染、动态内容和复杂的导航流程——使其适用于需要访问当前网络数据的 RAG 应用程序，包括分页、过滤器和客户端渲染背后的内容。

我们可以将其用作[检索器](/oss/python/langchain/retrieval)。它将展示此集成特有的功能。在了解之后，探索[相关的用例页面](/oss/python/langchain/rag)以学习如何将此检索器作为更大链的一部分使用可能会很有用。

### 安装

<CodeGroup>
```bash pip
pip install -U langchain-nimble
```
```bash uv
uv add langchain-nimble
```
</CodeGroup>

我们还需要设置我们的 Nimble API 密钥。您可以通过在 [Nimble](https://www.nimbleway.com/) 注册来获取 API 密钥。

```python
import getpass
import os

if not os.environ.get("NIMBLE_API_KEY"):
    os.environ["NIMBLE_API_KEY"] = getpass.getpass("Nimble API key:\n")
```

## 用法

现在我们可以实例化我们的检索器：

```python
from langchain_nimble import NimbleSearchRetriever

# 基本检索器
retriever = NimbleSearchRetriever(k=5)
```

## 在链中使用

我们可以轻松地将此检索器组合到用于问答的 RAG 链中：

```python
from langchain_core.output_parsers import StrOutputParser
from langchain_core.prompts import ChatPromptTemplate
from langchain_core.runnables import RunnablePassthrough
from langchain_openai import ChatOpenAI

# 创建一个 RAG 提示
prompt = ChatPromptTemplate.from_template(
    """仅根据提供的上下文回答问题。
如果无法根据上下文回答，请说明。

上下文：{context}

问题：{question}

回答："""
)

llm = ChatOpenAI(model="gpt-4o-mini")

# 配置检索器以获得全面结果
retriever = NimbleSearchRetriever(
    k=5,
    deep_search=True,
    parsing_type="markdown",
    include_domains=["wikipedia.org", "britannica.com", ".edu", ".gov"]
)


def format_docs(docs):
    return "\n\n".join(doc.page_content for doc in docs)


# 构建 RAG 链
chain = (
    {"context": retriever | format_docs, "question": RunnablePassthrough()}
    | prompt
    | llm
    | StrOutputParser()
)
```

```python
# 提问
response = chain.invoke("可再生能源和不可再生能源的关键区别是什么？")
print(response)
```

```output
根据提供的上下文，以下是可再生能源和不可再生能源的关键区别：

**可再生能源：**
- 在人类时间尺度上自然补充（太阳能、风能、水能、地热能、生物质能）
- 可持续且几乎取之不尽
- 通常产生很少或不产生温室气体排放
- 环境影响较小
- 近年来成本显著下降

**不可再生能源：**
- 无法快速补充的有限资源（煤炭、石油、天然气、核能）
- 最终将耗尽
- 燃烧会释放大量温室气体和污染物
- 气候变化的主要贡献者
- 目前仍提供全球大部分能源，但竞争力正在下降

上下文表明，可再生能源在提供环境效益的同时，正日益在成本上与化石燃料竞争。
```

## 高级配置

检索器支持针对不同用例的广泛配置：

| 参数 | 类型 | 默认值 | 描述 |
|-----------|------|---------|-------------|
| `k` | int | 10 | 返回的最大结果数 (1-20) |
| `deep_search` | bool | True | **深度模式**（默认）用于完整内容提取，或**快速模式**（False）仅用于 SERP 结果 |
| `topic` | str | "general" | 为特定内容类型优化搜索："general"、"news" 或 "location" |
| `include_answer` | bool | False | 在搜索结果旁生成 AI 驱动的摘要答案 |
| `include_domains` | list[str] | None | 白名单特定域名（例如 ["wikipedia.org", ".edu"]） |
| `exclude_domains` | list[str] | None | 黑名单特定域名以进行过滤 |
| `start_date` | str | None | 过滤日期之后的结果 (YYYY-MM-DD 或 YYYY) |
| `end_date` | str | None | 过滤日期之前的结果 (YYYY-MM-DD 或 YYYY) |
| `parsing_type` | str | "markdown" | 输出格式："plain_text"、"markdown" 或 "simplified_html" |
| `locale` | str | "en" | 搜索区域设置（例如 "en-US"） |
| `country` | str | "US" | 用于本地化结果的国家代码（例如 "US"） |
| `api_key` | str | 环境变量 | Nimble API 密钥（默认为 NIMBLE_API_KEY 环境变量） |

**高级配置示例：**

```python
from langchain_nimble import NimbleSearchRetriever

# 为学术研究优化的检索器
retriever = NimbleSearchRetriever(
    k=10,
    deep_search=True,
    topic="general",
    include_domains=["arxiv.org", "nature.com", "science.org"],
    start_date="2025-01-01",
    parsing_type="markdown"
)

docs = retriever.invoke("量子计算的最新进展")
```

## 最佳实践

### 快速模式 vs 深度模式

- **深度模式** (`deep_search=True`，默认)：
  - 从网页提取完整内容
  - 适用于需要完整内容的 RAG 应用程序
  - 最适合详细研究和构建知识库
  - 处理 JavaScript 渲染和动态内容

- **快速模式** (`deep_search=False`)：
  - 仅包含标题和摘要的快速 SERP 结果
  - 为性能敏感型应用程序优化
  - 最适合速度至关重要的高容量查询
  - 每次查询成本更低

### 过滤策略

**域名过滤：**

- 使用 `include_domains` 进行聚焦研究（学术、政府、可信来源）
- 使用 `exclude_domains` 过滤论坛、社交媒体或不可靠来源
- 结合两者以精确控制来源质量

**日期过滤：**

- 设置 `start_date` 和 `end_date` 用于时间敏感型查询
- 对于最近的新闻、时事或过时信息至关重要
- 格式："YYYY-MM-DD"（具体）或 "YYYY"（仅年份）

**主题路由：**

- 使用 `topic="news"` 为时事和新闻文章优化
- 使用 `topic="location"` 为本地企业和地理查询优化
- 使用 `topic="general"` 或省略以进行标准网络搜索

### 性能优化

1. **选择正确的模式**：对于速度至关重要的高容量查询，使用**快速模式** (`deep_search=False`)；对于全面的内容提取，使用**深度模式**（默认）
2. **调整结果数量**：从较小的 `k` 值开始，根据需要增加
3. **使用异步**：利用 `ainvoke()` 进行并发查询
4. **策略性缓存**：考虑缓存频繁查询
5. **明智过滤**：域名和日期过滤可减少噪音并提高相关性
