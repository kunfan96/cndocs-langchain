[**LangSmith Fleet**](/langsmith/fleet/index) 是一个企业代理平台，用于在您的组织内构建、共享和管理代理。本页面将其与类似平台进行对比，帮助您为团队选择合适的平台。

<div className="compact-first-col">

| **平台** | **选择条件...** |
| ------------ | ---------------- |
| [LangSmith Fleet](/langsmith/fleet/index) | 您希望在组织内构建和共享专用代理，保持模型无关性，并通过 LangSmith 实现完全的可观测性。**Fleet** 是唯一提供自托管部署路径并能通过 [Deep Agents](/oss/python/deepagents/overview) 将代理导出为代码的选项。 |
| Claude Cowork | 您希望从桌面端将开放式任务委托给 Claude 进行个人知识工作，并且设备上数据存储满足您的隐私要求。 |
| Amazon Quick | 您已在 AWS 上，并希望获得一个能直接访问您的 AWS 数据源和企业集成的 AI 助手。 |
| Google Workspace Studio | 您的组织使用 Google Workspace，您希望获得无需代码的代理，这些代理可在 Gmail、Drive 和 Sheets 内原生工作，无需离开 Google 生态系统。 |

</div>

### 目标用户

**Fleet** 涵盖组织范围和个人用例。团队可以构建专用代理以在组织内共享（例如，一个服务于整个运营组织的供应商接收代理，或一个每周为每位客户经理节省周一早上三十分钟的周报代理），任何用户都可以通过 Fleet 的通用默认聊天使用任何工具获得任何任务的帮助。

Claude Cowork 专为个人工作流程设计：每个用户在自己的机器上运行 Claude 进行开放式任务委托，而不是在团队内构建和共享代理。

Amazon Quick 和 Google Workspace Studio 是围绕回答问题和自动化工作流程构建的全劳动力平台，但主要不是为构建和共享专用代理而设计。

**Fleet** 还允许您设置工具级别的审批要求，以便代理在执行敏感步骤前与您确认，并提供一个[集中收件箱](https://smith.langchain.com/agents/inbox)用于审查、编辑和批准操作。

Claude Cowork 采用类似的“先向我展示计划”模式。Amazon Quick 提供通知，但没有用于审查所有代理操作的集中收件箱。

### 企业控制和访问

**Fleet** 提供 RBAC、基于属性的访问控制以及每个代理的共享权限（克隆、运行和编辑），而 Claude Cowork 不提供这些功能。对于需要管理哪些团队可以访问、运行或修改特定代理的组织来说，这是一个显著差异。

Amazon Quick 和 Google Workspace Studio 从各自的云平台（AWS IAM 和 Google Workspace 角色）继承访问控制，但两者都不提供 Fleet 的每个代理权限模型。

**Fleet** 在工作区级别管理支出，而不是通过每个用户或每个团队的上限。Claude Cowork、Amazon Quick 和 Google Workspace Studio 都提供更细粒度的支出控制。有关企业计费选项，请[联系销售](https://www.langchain.com/contact-sales)。

### 模型灵活性

**Fleet** 通过 OpenAI 或 Anthropic 聊天规范支持任何 LLM，包括来自 OpenAI、Anthropic、Google 和自托管提供商的模型。

Claude Cowork 仅限 Claude。Google Workspace Studio 使用 Gemini 3。Amazon Quick 支持的模型未从公开文档确认。

Google Workspace Studio 包含在 Google Workspace Business 和 Enterprise 计划中，无需单独购买，但它仅在 Google 生态系统内工作。Amazon Quick 需要现有的 AWS 基础设施，不包含捆绑的生产力套件。

**Fleet** 和 Claude Cowork 基本上与生态系统无关。

### 记忆、自我更新和学习

**Fleet** 代理可以使用专用的记忆系统在对话间持久化上下文，并且可以在从交互中学习时更新自己的指令、添加工具或移除工具。在此比较的四个平台中，只有 Fleet 支持代理自我修改。

### 可观测性和治理

**Fleet** 最明显的优势是其与 LangSmith 的原生连接。每次代理运行都在 LangSmith 中被跟踪，使得调试性能和大规模运行评估变得容易。

Claude Cowork、Amazon Quick 和 Google Workspace Studio 各自都有审计和活动日志，但没有一个能匹敌 Fleet 通过专用可观测性平台提供的跟踪、评估和调试深度。

### 代码导出和托管

**Fleet** 允许您通过 [Deep Agents](/oss/python/deepagents/overview)（Fleet 运行所基于的开源代理运行时）将您构建的任何代理导出为代码。导出的代理采用 MIT 许可，可以独立于 Fleet 部署、在代码中修改，或通过 [API](/langsmith/fleet/code) 直接集成到您自己的应用程序中。此比较中的其他平台均不提供代码导出路径。

**Fleet** 是此比较中唯一提供自托管部署选项的平台。对于有合规要求的团队，自托管和 BYOC（自带云）配置允许您完全在自己的基础设施内运行 Fleet。

Amazon Quick 原生提供企业级 AWS 基础设施。Google Workspace Studio 遵守 Google Workspace 数据承诺。Claude Cowork 在本地设备上存储数据，使其成为此比较中唯一将数据完全保留在外部服务器之外的平台。
