本笔记本介绍如何从 `Docugami` 加载文档。它提供了使用此系统相对于其他数据加载器的优势。

## 先决条件

1. 安装必要的 Python 包。
2. 获取工作区的访问令牌，并确保将其设置为 `DOCUGAMI_API_KEY` 环境变量。
3. 获取已处理文档的一些文档集和文档 ID，如这里所述：[help.docugami.com/home/docugami-api](https://help.docugami.com/home/docugami-api)

```python
# 您需要 dgml-utils 包才能使用 DocugamiLoader（如果您不使用 poetry，请直接运行 pip install，无需 "poetry run"）
!poetry run pip install docugami-langchain dgml-utils==0.3.0 --upgrade --quiet
```

## 快速开始

1. 创建一个 [Docugami 工作区](http://www.docugami.com)（提供免费试用）
2. 添加您的文档（PDF、DOCX 或 DOC），并允许 Docugami 将其摄取并聚类为相似文档集，例如保密协议、租赁协议和服务协议。系统支持的文档类型没有固定集合，创建的聚类取决于您的特定文档，您可以稍后[更改文档集分配](https://help.docugami.com/home/working-with-the-doc-sets-view)。
3. 通过开发者游乐场为您的工作区创建访问令牌。[详细说明](https://help.docugami.com/home/docugami-api)
4. 探索 [Docugami API](https://api-docs.docugami.com) 以获取已处理文档集 ID 的列表，或仅获取特定文档集的文档 ID。
6. 使用下面详述的 DocugamiLoader，为您的文档获取丰富的语义块。
7. 可选地，构建并发布一个或多个[报告或摘要](https://help.docugami.com/home/reports)。这有助于 Docugami 根据您的偏好改进语义 XML，使用更好的标签，然后将其作为元数据添加到 DocugamiLoader 输出中。使用自查询检索器等技术进行高精度文档问答。

## 与其他分块技术相比的优势

对文档进行适当的分块对于文档检索至关重要。存在许多分块技术，包括依赖空白和基于字符长度的递归分块分割的简单技术。Docugami 提供了一种不同的方法：

1. **智能分块：** Docugami 将每个文档分解为一个层次化的语义 XML 树，包含不同大小的块，从单个单词或数值到整个章节。这些块遵循文档的语义轮廓，提供比任意长度或基于简单空白的分块更有意义的表示。
2. **语义注释：** 块使用语义标签进行注释，这些标签在整个文档集中保持一致，即使文档的编写和格式不同，也能促进跨多个文档的一致层次查询。例如，在一组租赁协议中，您可以轻松识别关键条款，如房东、租户或续租日期，以及更复杂的信息，如任何转租条款的措辞，或特定司法管辖区在终止条款中是否有例外部分。
3. **结构化表示：** 此外，XML 树使用表示标题、段落、列表、表格和其他常见元素的属性来指示每个文档的结构轮廓，并且在所有支持的文档格式（如扫描的 PDF 或 DOCX 文件）中保持一致。它适当处理长文档特征，如页眉/页脚或多栏流，以实现干净的文本提取。
4. **附加元数据：** 如果用户一直在使用 Docugami，块还会用附加元数据进行注释。此附加元数据可用于高精度文档问答，不受上下文窗口限制。请参阅下面的详细代码演练。

## 加载文档

如果设置了 DOCUGAMI_API_KEY 环境变量，则无需显式将其传递给加载器，否则可以将其作为 `access_token` 参数传递。

```python
DOCUGAMI_API_KEY = os.environ.get("DOCUGAMI_API_KEY")
```

```python
docset_id = "26xpy3aes7xp"
document_ids = ["d7jqdzcj50sj", "cgd1eacfkchw"]

# 要加载给定文档集 ID 中的所有文档，只需不提供 document_ids
loader = DocugamiLoader(docset_id=docset_id, document_ids=document_ids)
chunks = loader.load()
len(chunks)
```

每个 [`Document`](https://reference.langchain.com/python/langchain-core/documents/base/Document)（实际上是实际 PDF、DOC 或 DOCX 的一个块）的 `metadata` 包含一些有用的附加信息：

1. **id 和 source：** 块在 Docugami 中来源的文件（PDF、DOC 或 DOCX）的 ID 和名称。
2. **xpath：** 文档 XML 表示中块的 XPath。对于直接引用文档 XML 中实际块的源引用很有用。
3. **structure：** 块的结构属性，例如 h1、h2、div、table、td 等。如果调用者需要过滤某些类型的块，这很有用。
4. **tag：** 块的语义标签，使用各种生成式和提取式技术。更多详情请参阅：[github.com/docugami/DFM-benchmarks](https://github.com/docugami/DFM-benchmarks)

您可以通过在 `DocugamiLoader` 实例上设置以下属性来控制分块行为：

1. 您可以设置最小和最大块大小，系统会尝试以最小的截断来遵守这些大小。您可以设置 `loader.min_text_length` 和 `loader.max_text_length` 来控制这些。
2. 默认情况下，仅返回块的文本。但是，Docugami 的 XML 知识图谱包含其他丰富信息，包括块内实体的语义标签。如果您希望返回的块包含额外的 XML 元数据，请设置 `loader.include_xml_tags = True`。
3. 此外，如果您希望 Docugami 在返回的块中返回父块，可以设置 `loader.parent_hierarchy_levels`。子块通过 `loader.parent_id_key` 值指向父块。这对于例如使用多向量检索器进行[小到大](https://www.youtube.com/watch?v=ihSiRrOUwmg)检索很有用。请参阅本笔记本后面的详细示例。

```python
loader.min_text_length = 64
loader.include_xml_tags = True
chunks = loader.load()

for chunk in chunks[:5]:
    print(chunk)
```

## 基本用法：用于文档问答的 Docugami 加载器

您可以像使用标准加载器一样使用 Docugami Loader 进行多文档的文档问答，尽管它提供了遵循文档自然轮廓的更好的块。有许多关于如何执行此操作的优秀教程，例如[这个](https://www.youtube.com/watch?v=3yPBVii7Ct0)。我们可以使用相同的代码，但使用 `DocugamiLoader` 以获得更好的分块，而不是直接使用基本分割技术加载文本或 PDF 文件。

```python
!poetry run pip install -U langchain-openai tiktoken langchain-chroma hnswlib
```

```python
# 对于此示例，我们已经为一组租赁文档处理了一个文档集
loader = DocugamiLoader(docset_id="zo954yqy53wp")
chunks = loader.load()

# 有意剥离语义元数据，以测试在没有语义元数据的情况下工作情况
for chunk in chunks:
    stripped_metadata = chunk.metadata.copy()
    for key in chunk.metadata:
        if key not in ["name", "xpath", "id", "structure"]:
            # 移除语义元数据
            del stripped_metadata[key]
    chunk.metadata = stripped_metadata

print(len(chunks))
```

```text
4674
```

加载器返回的文档已经分割，因此我们不需要使用文本分割器。或者，我们可以使用每个文档上的元数据，例如结构或标签属性，进行任何我们想要的后处理。

我们将直接使用 `DocugamiLoader` 的输出，以通常的方式设置检索问答链。

```python
from langchain_classic.chains import RetrievalQA
from langchain_chroma import Chroma
from langchain_openai import OpenAI, OpenAIEmbeddings

embedding = OpenAIEmbeddings()
vectordb = Chroma.from_documents(documents=chunks, embedding=embedding)
retriever = vectordb.as_retriever()
qa_chain = RetrievalQA.from_chain_type(
    llm=OpenAI(), chain_type="stuff", retriever=retriever, return_source_documents=True
)
```

# 使用示例查询尝试检索器
qa_chain("租户可以在其物业上放置哪些标识？")

## 使用 Docugami 知识图谱进行高精度文档问答

# 高级主题：使用文档知识图谱层次结构进行小到大检索

文档本质上是半结构化的，DocugamiLoader 能够导航文档的语义和结构轮廓，为其返回的块提供父块引用。这对于例如使用多向量检索器进行[小到大](https://www.youtube.com/watch?v=ihSiRrOUwmg)检索很有用。

要获取父块引用，您可以将 `loader.parent_hierarchy_levels` 设置为非零值。

```python
from typing import Dict, List

from docugami_langchain.document_loaders import DocugamiLoader
from langchain_core.documents import Document

loader = DocugamiLoader(docset_id="zo954yqy53wp")
loader.include_xml_tags = (
    True  # 用于来自 Docugami 知识图谱的附加语义
)
loader.parent_hierarchy_levels = 3  # 用于扩展上下文
loader.max_text_length = (
    1024 * 8
)  # 8K 字符大约是 2K 令牌（参考：https://help.openai.com/en/articles/4936856-what-are-tokens-and-how-to-count-them）
loader.include_project_metadata_in_doc_metadata = (
    False  # 不在向量元数据上过滤，因此移除以减轻向量负担
)
chunks: List[Document] = loader.load()

# 构建父块和子块的单独映射
parents_by_id: Dict[str, Document] = {}
children_by_id: Dict[str, Document] = {}
for chunk in chunks:
    chunk_id = chunk.metadata.get("id")
    parent_chunk_id = chunk.metadata.get(loader.parent_id_key)
    if not parent_chunk_id:
        # 父块
        parents_by_id[chunk_id] = chunk
    else:
        # 子块
        children_by_id[chunk_id] = chunk
```

```python
# 探索一些父块关系

        # 子块设置了父块 id
        print(f"父块 {parent_chunk_id}: {parents_by_id[parent_chunk_id]}")
        print(f"块 {id}: {chunk}")
```
